# PS Game Base · 個人遊戲庫

本機優先的 PlayStation 遊戲庫管理頁。原生 HTML / CSS / JavaScript，無須安裝 npm 套件，不會自動上傳資料。

換機或接續開發先看 [交接與執行進度](docs/HANDOFF.md)；協作、資料約束與 commit／發布規則見 [AGENTS.md](AGENTS.md)。2026-10-19 Chrome／Tampermonkey 的免助手授權與單筆獎盃查詢已實測成功，v0.4.5 接回正式白金同步。先前助手流程也曾完成實際補標；新免助手版本的全庫操作仍待驗收。換機前請依交接清單另行保存個人備份。

## 啟動

需要 Node.js 20 或以上。在 PowerShell 執行：

```powershell
cd D:\gitp\ps-game-base
npm start
```

開啟 http://127.0.0.1:4175 。請固定使用相同主機及連接埠，瀏覽器本機存檔依 origin 區分。不要直接雙擊 HTML（ES module、OAuth 與分頁回傳均需要 HTTP 來源）。靜態部署時以 `dist` 為網站根目錄即可。

## GitHub Pages 發布

發布設定檔為 `.github/workflows/deploy.yml`，沿用 EDF 專案的 Pages Actions 流程，直接將 `dist` 上傳發布，無須建置。

- 推送到 `main` 時自動發布；也可在 Actions 手動執行。手動選擇其他分支時會跳過部署。
- 發布前自動用本次 commit SHA 更新本機 JS／CSS 網址的 `?v=`，涵蓋入口、共用腳本及 ES module 相依檔案，避免新版 HTML 混用舊快取。直接發布 `dist/` 前可先執行 `node tools/version-assets.mjs <版本號>`；同次發布共用一個新版本號，不需更改 Tampermonkey 的腳本版本。
- GitHub repo 的 Settings → Pages → Build and deployment → Source 須選擇 **GitHub Actions**。
- 此 repo 的預設 Pages 網址為 `https://promise82114.github.io/ps-game-base/`；實際發布網址以 Actions 的部署結果為準。
- 已在腳本中允許 `https://promise82114.github.io` 回傳來源。更新網站後，仍須重新安裝／更新 Tampermonkey 中的整合腳本至 0.4.5。
- Google OAuth Client 的「已授權 JavaScript 來源」須加入 `https://promise82114.github.io`（僅 origin，不含 `/ps-game-base/`）。此設定需由 Google Cloud 管理者操作。
- 本機與 Pages 的瀏覽器存檔分開；可透過完整 JSON 備份搬移。
- 與 EDF 相同，首頁設定 `<meta name="robots" content="noindex, nofollow">`，要求支援此規則的搜尋引擎不要收錄。這不是存取控制，知道公開網址的人仍可開啟網站；個人匯入資料不隨靜態網站發布。參考 [Google noindex 說明](https://developers.google.com/search/docs/crawling-indexing/block-indexing)。

本次只準備發布設定，不會自動推送遠端或變更 GitHub / Google Cloud 設定。

## 使用

1. 按右上角「資料與同步 → 匯入 JSON」，選擇既有撈取腳本產生的 JSON，先看筆數與完整性，再確認匯入。
2. 圖片區塊右上角可直接選擇白金／追蹤／忽略；點遊戲名稱可編輯自訂分類、標籤與私人筆記，也可清除項目分類。
3. 側欄可篩選白金、忽略、追蹤與自訂分類；手機版使用分類下拉選單。忽略只是一般標記，不會自動從所有遊戲、自訂分類或搜尋結果中排除，是否顯示由使用者篩選決定。項目分類篩選器另提供「排除忽略」，預設不啟用，也不會變更儲存的標記。
4. 遊戲庫一次顯示所有符合搜尋與篩選的作品，可直接向下捲動，封面圖片延遲載入。勾選遊戲或「選取全部結果」，可跨篩選保留選取，再批次變更狀態或加入自訂分類。
5. 「資料與同步」可匯出遊戲 JSON、個人分類 JSON 或完整備份。清除瀏覽器資料、切換網址、換瀏覽器前先備份。

空庫提供示範模式；示範中的修改與匯入不寫入你的本機存檔，亦不能連接雲端。由「資料與同步 → 離開示範」返回。

## 分頁撈取更新

開發副本位於 `dist/scripts/ps-game-base.user.js`，版本 0.4.5，從 `D:\gitp\tampermonkey-scripts\ps-game-base\ps-game-base.user.js` 複製後獨立開發，原檔未修改。

1. 先在 Chrome / Edge 安裝 Tampermonkey。
2. 在頁面的「資料與同步」點「安裝 / 更新 Tampermonkey 腳本」，或將副本內容貼入 Tampermonkey 新腳本。
3. 回到管理頁，從右上角「資料與同步」按「更新遊戲庫」，保留管理頁開啟；官方遊戲庫會另開分頁。
4. 登入並選「已購買」。腳本在觀察到官方 `getPurchasedGameList` 查詢後，自動循序撈取，完成後回傳管理頁供預覽、確認匯入。
5. 若瀏覽器／官方登入跳轉使 opener 或網址片段失效，五分鐘後會提示。可在官方分頁開啟 PS Game Base 面板，手動同步、匯出 JSON 再匯入。

回傳限制來源為腳本內的 `MANAGER_ORIGINS`（允許本專案的 `http://127.0.0.1:4175`、`http://localhost:4175` 與 `https://promise82114.github.io`）。改埠或改用其他部署網址時，請將你信任的完整 origin 明確加入該清單，再更新已安裝的腳本。不可直接信任任意網址片段提供的來源，否則其他網站也可能開啟官方庫並接收資料。

管理頁同時核對官方 origin、它開啟的分頁物件與隨機 session；僅完整結果可自動回傳，部分結果需手動匯入。Bearer / Cookie 不會傳給管理頁、JSON 或 Drive；Bearer 只存在官方分頁閉包，Cookie 交由瀏覽器管理。切換 PSN 帳號前重新整理官方分頁。本版管理一個人的遊戲庫，未提供帳號隔離，不要混合匯入不同人的資料。

### 解析相容性與診斷

0.2.2 完整補回原版 0.1.3 的 `parsePayload` 與解析階段診斷。保留 `/recently-purchased`、JSON／批次 GraphQL、URL-encoded POST、Request 複本、無 Bearer 工作階段與管理頁回傳流程。修正 0.2.1 漏掉的「網址參數與表單本文合併」：例如操作名稱在網址、extensions 在表單時，現在可取得查詢碼；表單欄位優先於同名網址欄位。這個缺口已用合成請求重現並修正，但不能斷定使用者截圖的所有格式錯誤都由此造成。

更新 Tampermonkey 後，關閉舊官方分頁，從管理頁重新按「更新遊戲庫」，確認面板為 v0.4.5；仍在等待時，切換官方分類再回「已購買」。診斷列顯示計數、最多 6 個格式受限的操作名稱，以及最近失敗階段（請求本文、extensions JSON、請求標頭、Request 本文複本或 fetch 請求複本）。不顯示原始請求本文、網址、標頭、例外內容或權杖。「無 Bearer」是請求觀察結果，不等於授權失敗。

請提供診斷列與面板提示即可，不要提供 Cookie、Bearer、NPSSO 或含授權標頭的 HAR。Sony 真實登入後的同步與分頁回傳仍須實機驗收。

## 分類管理設計

| 行為 | 用途 |
| --- | --- |
| 項目分類 | 白金、忽略、追蹤三個互斥 Radio，可清除分類回到未分類 |
| 自訂分類，可複選 | 如週末雙人、劇情精選、親子同樂、挑戰清單；可新增、改名、刪除 |
| 自訂標籤 | 比分類更細的關鍵字，如短篇、控制器、需要攻略；以逗號分隔 |
| 私人筆記 | 記錄進度、擱置原因與下一次目標 |
| 批次整理 | 跨篩選保留選取後套用狀態或加入自訂分類 |
| 篩選與排序 | 名稱／標籤／筆記搜尋、平台、來源、項目分類、自訂分類；名稱與最近整理排序 |
| 同步差異 | 完整同步未出現的授權另外標示，保留遊戲與個人紀錄；部分同步不判定新缺少授權 |

每筆授權依下列順序選擇分組依據：非空的 `conceptId` → 非空的 `productId` → 自己的 `entitlementId`，相同分組 key 自動合併成一張作品卡，同時顯示 PS4／PS5 平台；相同分組下的同平台不同版別授權也一併收納。名稱不參與判斷，不同分組 key 不再交叉合併。因此有不同 concept 的項目即使 product 相同也不合併；一筆有 concept、另一筆沒有，也不僅因 product 相同而跨組合併。本版不提供手動合併／拆分操作。

例如「百英雄傳」PS4／PS5 匯出都沒有 `conceptId`，但 `productId` 同為 `UP4040-PPSA04721_00-EIYUDENHEROESPS5`，就會以該商品 ID 合併，仍保留兩筆不同的 entitlement／title ID。

卡片、遊戲概況與批次選取以作品計算，另外列出原始授權筆數。編輯視窗只保留一份共用的項目分類、自訂分類、標籤與筆記；可展開「版本與授權」查看各筆來源及 ID。原始遊戲 JSON 仍逐筆保留 entitlement，不會因畫面合併而刪除授權。

項目分類沿用既有存檔值：白金 = `已白金`、忽略 = `不再遊玩`、追蹤 = `想玩`；清除分類使用既有的 `未開始`。其他舊狀態仍相容讀取，未自動轉換；在新 UI 視為尚未選擇三種標記，編輯時提示原狀態，沒有重新分類就儲存仍會保留原值。

三種圖示均為本機 SVG（一般獎盃、圓圈叉、書籤），未引入套件或下載官方素材。選取時分別使用 `#75BDF6`／`#E65B62`／`#E9AD42`，搭配亮文字、加粗、邊框與淡色背景；未選取為灰階，不降低整個元件的 opacity。使用原生 Radio 的互斥與鍵盤操作，網站目前只有暗色主題。

圖片上的快捷 Radio 依白金／追蹤／忽略排列。滑鼠移入圖片時展開三個圖示，離開後只保留已選的那一個；未分類時不留圖示。選擇後立即沿用原本的作品更新與本機存檔流程，分類、統計、篩選與編輯視窗同步更新。Tab 進入圖片選取框後可繼續進入 Radio，以方向鍵切換；鍵盤焦點仍在圖示中時保持展開。無 hover／觸控指標裝置直接顯示三個選項，避免無法操作。清除分類仍可在編輯視窗進行。

追蹤取代收藏用途，已移除「我的收藏」、紅心、加入收藏與批次收藏。舊 `favorite` 欄位僅保留備份相容，不再影響分類或整理差異判定，也不會自動覆蓋既有白金／追蹤／忽略標記。

已移除評分輸入、卡片星等與評分排序。舊存檔中的 `rating` 僅為備份相容而保留，不顯示、不編輯，也不參與版本整理差異判定。

既有各版本的個人紀錄不自動覆寫。還沒有作品共用整理時，先採最近儲存的一份（時間相同時依來源紀錄 key 固定排序），內容不同會在編輯視窗提示。之後的編輯存成作品共用資料，舊版別紀錄仍留在個人 JSON／完整備份中。後續加入相同分組的版本會沿用作品整理；由單筆授權改為商品分組，或由商品分組改為 concept 分組時，也會讀取對應的舊整理。當新的分組 key 已有共用紀錄時，仍優先採用該紀錄。

平台與來源篩選必須由同一筆版本授權同時符合；結果卡片仍列出該作品所有版本。只有部分授權未出現在完整同步時顯示「部分版本授權未出現」，不會將整部作品當成消失。未出現不等於已退款、訂閱過期或確定失去授權。來源 `NONE` 包含免費遊戲，不標為付費；沒有來源的項目單獨顯示未分類。

後續可再擴充「本機實體遊戲紀錄」、「待玩優先順序／預計遊玩月份」及「智慧分類規則」。這些需要新的資料來源或操作規則。

## JSON 與資料保護

下載的匯出檔名使用瀏覽器本機時間，格式為 `YYYY-MM-DD_HH-mm`，例如 `ps-game-base-backup-2026-10-19_14-35.json`。遊戲庫各類 JSON、官方腳本 JSON／CSV 及獎盃測試 JSON 均包含年月日與時分；JSON 內既有 ISO 時間欄位及 Drive 固定備份檔名不變。

瀏覽器使用單一 localStorage key `ps-game-base.v1` 儲存容器，裡面的 `library` 與 `personal` 分離；個人 JSON 可獨立匯入／匯出。

```json
{
  "schemaVersion": 1,
  "kind": "ps-game-base-personal",
  "categories": ["週末雙人"],
  "records": {},
  "works": {
    "concept:CONCEPT_ID": {
      "status": "想玩",
      "favorite": false,
      "rating": 0,
      "categories": ["週末雙人"],
      "tags": ["合作"],
      "note": "和朋友一起玩",
      "updatedAt": "2026-10-16T00:00:00.000Z"
    }
  }
}
```

- 遊戲 JSON：`schemaVersion: 1`、`complete` 布林值、`games` 陣列；每筆必須有唯一的 `entitlementId` 和 `name`，其餘採白名單。
- 遊戲 JSON 匯入採 ID 合併；不存在於新完整資料的遊戲保留在庫內並標示，不刪除個人整理。一般遊戲匯出排除這些已標示缺少的歷史項目；完整備份保留它們。
- 個人 JSON 與完整備份先顯示差異：本機獨有、匯入獨有、內容衝突與相同筆數。預設合併，保留本機獨有進度、加入匯入獨有整理；衝突預設保留本機，也可逐筆或全部選擇來源內容。不根據時間自動覆蓋，明確清除的標記／空白筆記仍能選用。另可選只更新遊戲庫，或明確使用來源整份整理。分類名單在合併時取聯集。可先匯入分類、之後再匯入遊戲；暫無對應遊戲的紀錄仍會比較並保留。
- 個人資料的 `records` 保留舊版逐授權紀錄；可選的 `works` 保存作品共用整理，以 `concept:...` 為 key，缺少 concept 時改用 `product:...`，兩者都沒有則用 `entitlement:...`。舊 JSON 沒有 `works` 仍可匯入，新匯出與 Google Drive 完整備份會包含兩者。請使用新版頁面處理新備份，舊版頁面不識別新的作品分組依據。
- 完整備份：`kind: ps-game-base-backup`，包含 `library`、`personal`、`missingIds` 和匯出時間。匯入遊戲仍採合併，個人資料依預覽選擇處理；不是清空本機還原。合併另一裝置的備份不會把本機獨有遊戲標成最近同步未出現；官方完整同步仍維持原本的缺少標記流程。
- 檔案限制 5 MB；格式錯誤不變更目前資料。分類／標籤每項上限 100 字，筆記上限 10,000 字。
- 套用匯入或確認上傳前，以獨立 key `ps-game-base.v1.before-import` 保存一份操作前完整備份（下一次套用會更新此備份），可在「資料與同步」匯出後重新匯入；要精確恢復原個人整理時，請選使用來源整份整理。無法保存此備份時停止操作。比較視窗亦可另存來源 JSON。預覽和取消不會寫入資料；不寫入 token。
- 操作結果同時顯示於對話框內的持續訊息，以及使用 Popover top layer 的通知，避免被 modal 遮罩蓋住。
- 寫入失敗會提示立即匯出。偵測其他分頁更新時暫停此頁寫入，避免舊分頁覆蓋新資料。
- 圖片只接受 HTTPS，文字以 textContent 顯示。圖片載入失敗顯示名稱縮寫；不額外擷取遊玩時數、價格或付款資料。

## Google Drive

沿用 EDF 專案的公開 OAuth Client ID，沒有 Client Secret。共用原有 `shared/google-auth.js` 與 `shared/drive-appdata.js` 的副本，使用獨立檔名 `ps-game-base.json`。

Google GIS Token Model 在使用者點擊後取得暫存 access token；Drive scope 僅 `drive.appdata`，備份位於應用程式隱藏資料夾。請確認此 OAuth Client 的「已授權 JavaScript 來源」含你使用的 origin（本機預設 `http://127.0.0.1:4175`）；同時啟用 Drive API，測試模式下帳號需在測試使用者中。這些 Google Cloud 設定並未由本專案自動變更。

操作為「載入授權服務 → 再次點擊連接 → 下載並比較／比較並上傳 → 確認差異」。下載只開啟比較，不直接取代本機；上傳會重新讀取雲端，顯示與 JSON 匯入相同的差異和衝突選擇，確認後才將合併結果寫到雲端及本機。上傳失敗時本機維持原狀；若雲端成功但本機儲存失敗，會分別提示結果。上傳前必須先讀取版本；檔案版本、ETag / If-Match 保護更新，衝突時停止。同名多份檔案也會停止。斷線只清除本分頁 token，不刪除雲端備份，亦不撤銷 Google 帳號的既有授權。

版本保護從 [Drive v2 檔案中繼資料的 JSON `etag`](https://developers.google.com/workspace/drive/api/reference/rest/v2/files) 取得，不依賴檔案下載回應的 ETag 標頭；受保護更新使用同版 API 的 `PUT` 搭配 `If-Match`。查詢、下載內容與首次建立仍使用 v3。若缺少有效版本或 ETag，仍停止上傳；下載期間變更及上傳時 HTTP 412 也會阻止覆蓋。`tests/drive-appdata.test.mjs` 模擬這些情境，未代替真實 Google 帳號讀寫驗收。

官方文件：[Token Model](https://developers.google.com/identity/oauth2/web/guides/use-token-model)、[Drive appDataFolder](https://developers.google.com/workspace/drive/api/guides/appdata)、[Drive v2 更新檔案](https://developers.google.com/workspace/drive/api/reference/rest/v2/files/update)。
